기본과제 · 고정 데이터로 전체 흐름 익히기

  1. 현황: 기본 미션의 스키마·데이터를 확인합니다. 테이블 생성 → 프로시저 최초 등록을 실행합니다. 이미 준비되었으면 반복 생성하지 않습니다.
  2. 학습데이터: 학습·TEST CSV 다운로드 → 파일 선택 → 최초 적재 → 원본 데이터 조회. RAW와 CLEAN을 각각 선택하여 전처리 실행·저장 → 저장값 조회를 수행합니다.
  3. 모델 생성·비교: RAW·CLEAN 각각 최초 학습 후 TEST 평가·새로고침으로 같은 TEST의 정확도·오분류를 비교합니다. 원하는 모델을 기본 예측 모델로 지정할 수 있습니다.
  4. 예측 실행: 예측 CSV 다운로드 → 파일 선택·적재 → 입력 조회 → RAW 또는 CLEAN 선택 → 예측 실행. 4단계에서도 모델을 바로 바꿀 수 있습니다.
  5. 현황: 최종 현황 확인 → 네 단계의 세부 작업 확인 → 기본과제 성공 도장과 본인 정보를 PPT에 캡처합니다.

기본과제는 SQL 수정 없이 수행할 수 있습니다. 코딩도움말로 실행 흐름을 확인하고 데이터·전처리·평가 결과를 본인의 말로 설명하세요.

미션과제 · 예시를 선택하고 SQL로 구현하기

  1. 미션 선택: 12종의 스키마 조회 → 데이터 조회로 목적·활용 사례·설명변수의 의미와 유효값을 확인하고 이 미션 선택을 누릅니다. 선택은 계정별로 저장됩니다.
  2. 객체 생성: 스키마 조회의 ① DATA → ② PREPARED → ③ PREDICT → ④ RUN 순서로 SQL을 확인합니다. 테이블 SQL은 sql/custom/mission/01_tables.sql, 프로시저 SQL은 sql/custom/mission/02_procedure.sql에 저장합니다.
  3. DB 적용: SQL Developer에서 본인 발급 계정으로 접속하여 테이블 SQL 전체, RUN SQL 전체를 차례로 F5 실행합니다. 웹에서 SQL 실행 결과 연계를 누릅니다.
  4. 원본 적재: 선택 미션의 학습·TEST CSV 다운로드 → 학습데이터 탭에서 파일 선택 → CSV 교체 적재 → 원본 데이터 조회.
  5. 전처리: 코딩도움말의 선택 미션 SQL로 RAW·CLEAN PREPARE를 각각 직접 실행·COMMIT합니다. SQL 실행 결과 연계 → 저장값 조회로 FIT_YN·EXCLUDE_REASON·TRAIN·TEST를 확인합니다.
  6. 모델·평가: RAW·CLEAN INIT(최초 생성) 또는 RETRAIN(전체 다시 학습)을 직접 실행합니다. SQL 실행 결과 연계 후 화면에서 두 모델을 각각 선택하여 선택 모델 TEST 평가를 수행합니다.
  7. 예측·증적: 예측 CSV를 화면에서 적재 → 모델 선택·예측 실행 → 현황 최종 확인 → 미션과제 성공 캡처. 수정한 SQL과 수정 이유도 보고서에 남깁니다.

테이블 생성 SQL은 해당 테이블이 있으면 삭제한 뒤 다시 만듭니다. 기존 행이 삭제되므로 최초 생성 또는 구조 교체 때만 실행하세요. 미션 변경은 객체 구조·RUN·CSV·전처리·모델을 새 주제에 맞추는 작업까지 필요합니다.

창의과제 · 본인 데이터와 SQL로 해결하기

  1. 설계: 해결할 문제·활용 상황, 데이터 출처, 식별키·설명변수·타깃, TRAIN/TEST 분할과 별도 예측 입력을 정합니다.
  2. 직접 구현: sql/custom/creative/01_tables.sql·02_procedure.sql의 이름·입출력 규약을 읽고 테이블·프로시저 SQL을 직접 작성해 DB에 적용합니다. 웹은 생성 SQL·실행 답안을 제공하지 않습니다.
  3. 적재·전처리: 웹의 SQL 실행 결과 연계로 객체를 확인하고 본인 CSV를 업로드·적재합니다. 원본 조회 → 직접 RAW/CLEAN 전처리 → COMMIT → 다시 연계 → 저장값 조회 순서로 확인합니다.

창의 원본은 TRAIN·TEST·별도 예측 합계 10,000건 이하입니다. 직접 SQL 생성·누적 적재도 포함하며 RAW/CLEAN 준비행을 원본 사례로 다시 세지 않습니다.

파일 저장은 DB 적용과 별개입니다. SQL Developer에서 파일 전체를 열고 선택 영역을 해제한 뒤 F5로 실행합니다. Ctrl+Enter는 커서의 한 문장만 실행합니다. 생성 SQL에는 테이블·컬럼 COMMENT도 포함되므로 첫 CREATE의 성공부터 확인하세요.

프로시저 수정은 파일 전체 CREATE OR REPLACE를 실행합니다. ALTER PROCEDURE COMPILE만으로 수정한 로컬 파일이 적용되지는 않습니다. 기본과제는 수정 후 프로시저 다시 등록을 사용할 수 있습니다. SQL 적용에는 웹 서버 재시작이 필요 없습니다.

미션·창의는 DATA·PREPARED·PREDICT·RUN 이름, p_action·p_mode·p_result·p_sql 인자를 유지합니다. EVALUATE는 VARIANT·ACTUAL·PREDICTED·N, PREDICT는 CASE_ID·PREDICTED·PROBABILITY를 반환합니다.

객체·프로시저 입출력 규약 상세 보기

CSV·정제·재학습에서 지킬 규칙
  • CSV는 UTF-8(또는 BOM), 첫 줄 영문 헤더, 쉼표 구분입니다. 세 과제 모두 웹 업로드는 파일당 2 MiB·5,000행까지입니다. 대상 테이블을 먼저 만들고 실제 컬럼 이름과 맞추세요.
  • CSV 교체 적재는 대상 테이블의 기존 행을 교체합니다. 파일 선택만으로 DB는 바뀌지 않습니다. 화면 확인 메시지에서 대상·범위를 확인하세요. 적재는 한 개의 바인드 INSERT를 500행씩 묶어 처리합니다.
  • 미션 CSV는 학습·TEST 1,500행(TRAIN 1,200 / TEST 300), 예측 30행입니다. 합성 데이터의 설명변수는 0~100 지수입니다. 빈 값·unknown·999999 등 결함을 점검하고 TEST와 정답은 성능을 높이려고 바꾸지 마세요.
  • 원본·프로시저를 바꾸면 전처리 저장 → 전체 다시 학습 → 연계(미션·창의) → TEST 재평가 순서입니다. 전체 다시 학습은 기존 모델을 지우고 현재 TRAIN 전체로 다시 만듭니다.
  • PREPARED의 준비값·FIT_YN만 수동 수정했다면 COMMIT 후 재학습합니다. PREPARE를 다시 실행하면 수동 수정한 준비값이 교체됩니다.
  • 처음 상태로 되돌릴 때는 데이터 비우기·전처리값 비우기·모델 삭제·확정 해제·오브젝트 삭제 중 필요한 범위만 선택합니다. 미션은 관련 SQL 가이드, 창의는 직접 작성한 SQL로 수행합니다.
코딩도움말과 예측 결과 읽기

화면 → 이벤트 → API → 서비스 → DB 연결 → 실행 SQL 순서로 실제 파일을 추적합니다. 왼쪽 파일·구간을 선택하면 오른쪽 파일 전체에서 해당 위치로 이동합니다.

기본·미션의 실행 SQL에는 원본과 현재 선택값을 적용한 실행용 런타임 SQL이 함께 나옵니다. 생성 미리보기와 성공한 실제 조회 기록을 구분하며 도움말을 열어도 DB 작업은 실행되지 않습니다.

식별키는 파랑, 설명변수는 초록, 타깃은 보라, 기타는 회색입니다. 색과 역할 배지를 함께 읽으세요. 예측은 학습과 같은 특성 이름·의미·단위·전처리를 사용합니다.

예측 입력과 PREPARED 값은 DB에 저장됩니다. 기본·제공 미션 프로시저의 분류·확률은 조회 결과이고 화면 기록은 새로고침하면 지워집니다. 서버에는 최종 성공 확인용 요약이 남습니다. 창의 프로시저의 별도 결과 저장은 본인이 구현한 SQL에 따릅니다.

저장·적재 중에는 진행바가 표시됩니다. 정상 완료 알림은 잠시 뒤 사라지며 오류와 확인 레이어는 직접 확인합니다. 문의 시 오류 코드·실행 작업을 전달하고 비밀번호·Wallet은 보내지 마세요.

4. 배포 확인과 다음 수정 반영
  1. Deploys / Events에서 Git 최신 커밋과 배포 커밋을 비교하고 Live 상태를 확인합니다. 자동 배포가 꺼져 있으면 Manual Deploy → Deploy latest commit을 실행합니다.
  2. 표시된 HTTPS 주소의 /healthz를 열어 {"status":"ok"}를 확인합니다. 이는 웹 프로세스 응답이며 DB 연결 성공을 뜻하지 않습니다.
  3. Render 메인에서 학번·이름·DB 비밀번호 → 연결 테스트 → 로그인합니다. 서버 DB_PASSWORD와 일치하고 DB 접속에 성공해야 로그인됩니다. 입력값 저장은 학번·이름만 저장하며 비밀번호는 브라우저 저장소·student.env에 쓰지 않습니다.
  4. 수정 후 본인 Git에 다시 -Push합니다. Render의 On Commit 배포와 최신 커밋을 확인한 뒤 새로고침합니다. 재배포·재시작 후에는 다시 로그인합니다.
