원본을 준비하고, 모델을 만들고, 결과를 비교합니다

같은 화면으로 기본은 버튼 실행, 미션은 SQL 가이드 실행·수정, 창의는 직접 SQL 설계를 배우고 결과를 확인합니다.

1. 오늘 가르칠 핵심

원본 DATA → INSERT SELECT → 준비값 PREPARED → FIT_YN=Y로 학습 → 같은 TEST로 비교 → 새 데이터 예측

  • 원본은 그대로 둡니다. 전처리한 값은 PREPARED에 따로 저장합니다.
  • RAW와 CLEAN은 별도 모델입니다. CLEAN은 RAW 모델에 정제를 덧붙이는 작업이 아닙니다.
  • 결과가 좋아졌는지 직접 확인합니다. 정제나 데이터 증가가 정확도 향상을 보장하지는 않습니다.

Oracle 프로시저의 DBMS_DATA_MINING.CREATE_MODEL2가 만듭니다. 기본은 웹 버튼으로 호출하고 미션·창의는 학생이 SQL Developer에서 직접 호출합니다.

2. 테이블 세 개와 프로시저 하나를 준비합니다

소유자는 학번이 아니라 발급 DB 계정입니다. 아래 STUDENT00은 예시이며 학생 본인의 계정으로 바꿉니다. 화면과 제공 SQL은 실제 로그인 계정의 소유자를 테이블·프로시저·모델명에 붙입니다. 계정 확인 가드로 다른 계정에서의 생성·삭제를 중단하며 직접 작성할 때도 같은 확인을 적용합니다. CURRENT_SCHEMA 변경만으로 접속 계정을 대신하지 않습니다.

역할기본미션창의
원본STUDENT00.OML_BASIC_DATASTUDENT00.OML_MISSION_DATASTUDENT00.OML_CREATIVE_DATA
전처리 저장STUDENT00.OML_BASIC_PREPAREDSTUDENT00.OML_MISSION_PREPAREDSTUDENT00.OML_CREATIVE_PREPARED
새 예측 원본STUDENT00.OML_BASIC_PREDICTSTUDENT00.OML_MISSION_PREDICTSTUDENT00.OML_CREATIVE_PREDICT

실습: 기본과제는 테이블·프로시저 준비 후 바로 실행합니다. 미션은 선택 미션 SQL 가이드를 적용·수정하고 창의는 SQL을 직접 작성합니다.

확인: 현황에서 네 객체의 준비 상태를 봅니다. 객체가 없으면 표시된 이름으로 생성합니다. 객체 미생성은 DB 접속 실패가 아닙니다.

원본은 오류 문자도 보존하도록 VARCHAR2에 저장합니다. 전처리 후 숫자는 sql/prepared_table.sql의 NUMBER 컬럼에 저장합니다.

확인 질문 · CREATE TABLE 파일을 고치면 기존 컬럼도 바뀌는가?

아닙니다. 기존 컬럼 변경은 ALTER로 적용합니다. 삭제·재생성은 저장된 행을 지울 수 있습니다.

3. 원본을 적재하고 조회합니다

  1. 기본의 고정 미션에서 데이터 조회·스키마 조회·CSV 다운로드를 확인합니다. 다른 미션으로 선택할 수 없습니다.
  2. 세 과제 모두 대상 테이블을 준비한 뒤 화면의 CSV 교체 적재를 실행합니다.
  3. 웹에 연결하여 TRAIN·TEST·사용 여부를 조회합니다. 기본은 ?, 미션은 선택 SQL 가이드로 해당 흐름을 봅니다.

확인: 기본 원본은 TRAIN 330행, TEST 360행, 미사용 30행입니다. TEST와 정답은 비교 기준이므로 바꾸지 않습니다. 직접 수정은 같은 계정의 SQL Developer에서 하고 COMMIT합니다.

확인 질문 · CSV 적재 중 중복 키 오류가 나면 이전 행은?

DELETE와 INSERT를 함께 ROLLBACK하여 이전 행을 보존합니다. 테이블 자체는 유지합니다.

4. 전처리 → 학습 → 비교 → 예측을 실습합니다

할 일DB에서 하는 일확인할 것

② 최초 학습선택 방식의 TRAIN·FIT_YN=Y를 CREATE_MODEL2로 학습모델명·생성 상태
③ TEST 비교같은 Y/TEST를 평가정확도·오분류

RAW와 CLEAN은 무엇이 다른가?

둘 다 빈 칸과 숫자로 바꿀 수 없는 값은 NULL로 저장합니다. CLEAN은 범위 밖 숫자도 NULL로 저장합니다. 변환은 PREPARE의 INSERT SELECT에서 하고, 모델은 PREPARED를 단순 조회합니다.

실습: RAW 전처리·최초 학습 → CLEAN 전처리·최초 학습 → 같은 TEST 비교. 기본은 화면에서 실행합니다. 미션·창의는 직접 SQL로 전처리·모델 생성을 실행한 뒤 웹의 연결·상태를 확인하고 TEST를 비교합니다. 한 번에 선택 모델 하나만 만듭니다.

데이터를 바꾸면 무엇을 다시 실행하는가?

바꾼 내용다음 실행
원본 값·정제 SQLDB 수정·적용 → 전처리 저장 → 전체 다시 학습
PREPARED 값·FIT_YNDB 수정·COMMIT → 전체 다시 학습
새 TRAIN 추가INSERT → VALIDATE → COMMIT → 전처리 저장 → 전체 다시 학습

전처리 재실행은 선택 방식의 준비값과 수동 수정값을 원본 기준으로 교체합니다. 재학습은 전처리를 다시 하지 않고 저장된 준비값을 사용합니다.

전체 다시 학습은 기존 모델 DROP → 전체 학습 제공 행으로 CREATE입니다. 데이터가 2배·3배가 되어도 같습니다. 선택 모델 삭제는 그 모델만 지웁니다. 모델 생성·삭제는 DDL 자동 커밋을 포함합니다.

확인 질문 · FIT_YN을 N으로 바꾼 뒤 전처리부터 다시 실행해도 되는가?

수동 변경값을 쓰려면 COMMIT 후 재학습합니다. 전처리부터 다시 실행하면 FIT_YN도 원본 기준으로 다시 만들어집니다.

예측 컬럼과 실행 성공의 의미

특성의 이름·타입·의미·단위를 학습과 맞춥니다. 순서는 달라도 됩니다. 기본 특성은 숫자 네 개(RETURN_PCT·RANGE_PCT·VOLUME_CHANGE_PCT·CLOSE_PRICE)와 STOCK입니다. CASE_ID는 행 식별자, SIGNAL은 정답이며 특성이 아닙니다.

PREDICTION(모델 USING d.*)의 d는 전처리된 예측값입니다. 함수에서는 CASE_ID·SIGNAL을 생략할 수 있지만 웹 테이블의 운영 컬럼은 유지합니다. 예측 CSV의 SIGNAL은 비우거나 생략할 수 있습니다. 누락·오타가 있어도 실행될 수 있으므로 실행 성공과 예측 품질을 따로 확인합니다.

reference/tests/verify_prediction_contract.py의 당시 CLEAN 모델 20조건 검사에서는 숫자 속성을 모두 빼자 30행 중 22행의 예측이 달라졌습니다. 당시 STOCK은 등록 속성에서 제외되어 있었습니다. 이 결과를 다른 모델에 일반화하지 않습니다. 변환하지 않은 unknown은 ORA-01722, 맞지 않는 DATE·RAW 타입은 ORA-00932가 날 수 있습니다.

모델 딕셔너리에서 확인할 것
  • USER_MINING_MODELS: 모델명·알고리즘·생성 시각.
  • USER_MINING_MODEL_ATTRIBUTES: 등록 특성과 타깃.
  • USER_MINING_MODEL_SETTINGS: 지정값·기본값. PREP_AUTO와 전처리 SQL은 별개입니다.
  • USER_MINING_MODEL_VIEWS: 실제 상세 뷰 이름. 제공된 조회 SQL을 복사합니다.
  • USER_MINING_MODEL_XFORMS: 모델에 등록한 변환. PREPARE의 CASE·TO_NUMBER는 여기에 저장되지 않아 0행일 수 있습니다.
  • USER_OBJECTS: 모델 ID·VALID. 웹의 최신 여부·확정과는 다릅니다.

USER_는 본인 소유, ALL_는 접근 가능한 객체, DBA_는 별도 권한이 필요한 전체 정보입니다. TEST 정확도는 별도로 평가합니다. 정상 0행과 조회 오류를 구분합니다. 수정 위치는 sql/queries/dictionary_*.sql과 backend/model_dictionary.py입니다.

5. 실행 → 가이드 수정 → 직접 설계로 확장합니다

기본 · 준비 후 실행하며 원리를 설명

고정 기본 미션의 데이터·스키마를 먼저 확인합니다. 환경과 객체를 준비하면 SQL 직접 수정 없이 화면 클릭으로 CSV 적재·전처리·학습·TEST 비교·예측을 실행할 수 있습니다. 학생이 원본·준비값·모델의 관계와 같은 TEST를 사용하는 이유를 설명하게 합니다.

미션 · 선택 데이터의 SQL 가이드를 실행·수정

  1. 10종 중 하나를 선택하고 CSV의 식별키·설명변수·타깃·원래 값을 확인합니다.
  2. 스키마 조회의 ① DATA → ② PREPARED → ③ PREDICT 순서로 테이블 생성 SQL을 확인합니다.
  3. 선택 미션 SQL 가이드의 RUN 등록 SQL과 각 단계의 전처리·모델·TEST·예측 SQL을 사용합니다. 기본 주식 예제를 담은 별도 생성 준비 팝업은 제공하지 않습니다.
  4. SQL을 복사해 실행하거나 01_tables.sql·02_procedure.sql로 내려받아 sql/custom/mission/에 직접 저장·수정합니다. 웹은 로컬 파일을 자동으로 덮어쓰지 않습니다.
  5. 발급 DB 계정에서 계정 확인 → 테이블 → RUN 순서로 F5 적용 → 화면 CSV 적재 → 직접 PREPARE → 모델 생성 → 웹 연결·상태 확인 → 조회·TEST 비교·예측을 실행합니다. CSV 적재는 화면에서 실행하며 테이블 생성·전처리·학습·삭제는 직접 SQL로 수행합니다.

가이드 SQL은 선택한 미션의 컬럼·분류 이름을 반영합니다. 전처리·TRAIN 오류행의 학습 제외 기준과 사유(FIT_YN·EXCLUDE_REASON)를 점검·보완하고 변경 이유를 설명하게 합니다. 고정 TEST와 정답은 보존합니다.

재생성: 각 CREATE TABLE 앞의 짧은 PL/SQL은 해당 테이블이 있을 때만 삭제합니다. 재실행하면 그 테이블 행이 삭제되며 DDL은 취소할 수 없습니다. 미션 변경 뒤에는 RUN 적용·CSV 적재·전처리 저장·재학습도 진행합니다.

창의 · 본인 SQL을 직접 작성

기본·미션에서 익힌 흐름으로 문제·데이터·테이블·전처리·모델·검증을 직접 설계합니다. sql/custom/creative/01_tables.sql·02_procedure.sql에는 고정 이름·입출력 규칙만 있으며 실행 답안은 없습니다. 미션과 같이 객체·CSV·전처리·모델을 직접 SQL로 준비한 뒤 웹에 연결해 조회·TEST 평가·예측을 활용합니다. 웹은 연결·메타데이터·실행 가능 여부를 확인하며 안내 쿼리를 제공하지 않습니다.

고정할 것: 객체 이름 네 개, 인자 네 개, 결과 형식입니다. PREPARED의 CASE_ID·PREP_MODE·SOURCE_KIND·USE_YN·FIT_YN·EXCLUDE_REASON·PREPARED_AT도 유지합니다. 특성·타깃은 SQL에서 정하고 웹 코드는 수정하지 않습니다.

객체가 없다면: 누락된 이름·컴파일 오류·인자 불일치를 진단합니다. 미션은 선택 미션 SQL 가이드를 적용하고 창의는 직접 작성한 SQL을 고칩니다. DB 접속 실패와 구분합니다.

창의 원본은 직접 SQL·누적 적재를 포함해 총 10,000건 이하입니다. 기본의 웹 CSV 적재 파일당 5,000행·2MiB 제한과 구분합니다. 미션은 로컬 CSV 적재기 또는 SQL Developer 데이터 가져오기로 적재하고, 창의는 적재 방법을 직접 구현합니다.

고정 입력·출력과 자동 연결 코드

입력 p_action·p_mode, 출력 p_result·p_sql을 유지합니다. EVALUATE 결과는 VARIANT·ACTUAL·PREDICTED·N, PREDICT 결과는 CASE_ID·PREDICTED·PROBABILITY입니다. CSV 헤더는 실제 컬럼과 비교하고 표는 반환 컬럼을 표시합니다.

확인 질문 · 미션과 창의의 지원 범위는 어떻게 다른가?

미션은 선택한 데이터에 맞는 실행 SQL을 가이드로 제공합니다. 창의는 안내 쿼리 없이 본인이 SQL을 직접 작성하고 연결·실행 여부와 오류 진단으로 확인합니다.

6. 파일 저장과 DB 적용을 구분합니다

  1. 기본은 버튼 옆 ?에서 Oracle 코드를, 미션은 선택 미션의 SQL 가이드를 봅니다. 창의는 본인 SQL을 점검합니다.
  2. 수정 위치에서 파일·줄·검색 키워드를 찾습니다.
  3. 프로시저 파일을 수정했다면 같은 계정에서 전체 F5 실행합니다.
  4. 전처리 저장 → 재학습 → 같은 TEST 비교를 합니다.

파일 저장만으로 DB는 바뀌지 않습니다. 웹은 DB에 저장된 프로시저를 호출합니다. 객체 확인 버튼은 조회만 하며 생성·컴파일하지 않습니다.

미션 CSV 도움말은 행별 INSERT 목록 대신 로컬 파일 명령과 바인드 SQL 한 문장을 보여 줍니다. scripts/load_mission_csv.py에서 --file·--owner를 지정해 검사한 뒤, 기존 행 교체에 동의할 때만 --replace를 추가합니다. 첫 줄 영문 헤더·쉼표 구분·UTF-8/BOM을 사용합니다.

500행씩 같은 커서의 executemany로 전달하고 마지막 한 번만 COMMIT합니다. 오류가 나면 교체 전체를 ROLLBACK합니다. 1,500행은 3묶음이며 전체 바인드 데이터를 실행 기록에 복사하지 않습니다. 웹 기본과제도 같은 묶음 실행기를 사용합니다.

DB 작업은 한 번에 하나이며 최대 1개 연결의 풀을 재사용합니다. 최초 물리 연결만 공통 세션 설정을 실행합니다. 로그인 비밀번호 확인은 새 연결을 사용하고, 로그아웃·계정 변경 때는 이전 풀을 정리합니다. 소스 변경 감지는 유지하면서 RAW/CLEAN 공통 조회를 공유합니다.

파일별 적용 방법
  • 기본 정의: 웹 테이블·프로시저 준비 또는 .\scripts\db-init.ps1. 기존 데이터를 보존하며 모델 학습은 하지 않습니다.
  • 미션 정의: 선택 미션의 01_tables.sql → 02_procedure.sql을 내려받거나 수정한 후 직접 적용합니다.
  • 창의 정의: 같은 이름의 두 파일에 본인이 SQL을 작성·적용합니다. 기본 db-init은 미션·창의 폴더를 적용하지 않습니다.
  • 적용 확인: USER_OBJECTS의 VALID, USER_ERRORS 0행, USER_SOURCE의 수정 원문 확인.
  • 조회·적재 .sql: 다음 작업에 반영. 프로시저 컴파일 불필요.
  • Python: 서버 재시작 후 로그인. HTML·JS·CSS: Ctrl+F5. SQL만 변경하면 서버 재시작 불필요.

파일 저장만으로 DB는 바뀌지 않습니다. 데이터를 보존할 컬럼 변경은 ALTER를 적용합니다. 미션의 DROP 포함 생성 SQL은 해당 테이블을 삭제·재생성합니다. DDL은 자동 커밋되며 ALTER PROCEDURE COMPILE은 DB 저장 원문만 다시 컴파일합니다.

도움말·메시지 사용법

제목 드래그·방향키로 이동하고 최소화·최대화·복원·ESC 닫기를 사용합니다. 최소화 후 본문을 조작할 수 있습니다. 작업 확인창의 취소·닫기·ESC는 실행하지 않습니다.

자세히 보기에는 오류 원인·누락 객체명·진단 결과처럼 다음 행동에 필요한 내용을 담습니다. 미션·창의 연결 진단은 생성 SQL 예제를 중복 제공하지 않습니다. 요약과 같은 내용만 반복한다면 표시할 필요가 없습니다.

버튼에서 SQL까지 · 호출 흐름으로 코드 읽기

코딩도움말의 화면 버튼(Jinja) → 이벤트(JavaScript) → API(FastAPI) → 서비스(Python) → DB 연결 → 실행 SQL(Oracle) 상자를 선택합니다. 왼쪽은 파일별로 묶고 그 아래 함수·실행 구간을 표시합니다. 오른쪽 파일 전체에서 선택 구간으로 이동하므로 앞뒤 문맥을 함께 읽을 수 있습니다. 같은 파일은 스크롤만 이동하며 다른 파일은 원문을 바꿉니다. 선택 구간 복사와 파일 전체 복사를 구분합니다. 핵심 모델 비교표는 내부 스크롤 없이 전체 결과를 보여 줍니다. 각 과제의 현황 상단에는 객체 준비·데이터/전처리·모델/TEST·예측 성공 여부가 모입니다. RAW/CLEAN TEST 평가와 새 입력 예측까지 완료하고 현황을 확인하세요. 모든 단계가 성공이면 이름·학번·DB 계정·미션명·확인 시각이 담긴 최종 실습 현황을 캡처하여 PPT 증적자료로 사용하세요. 데이터·모델·미션·예측 입력이 바뀌면 관련 단계를 다시 확인해야 합니다. 기본과제 4단계에서는 RAW/CLEAN을 직접 선택해 예측합니다. 별도 확정 버튼 없이 실행 성공 시 사용 모델을 저장하며, 3단계에서는 기본 예측 모델을 미리 지정할 수 있습니다. 분류·확률은 화면 조회 결과이며, 예측 입력·전처리 값은 DB에 저장됩니다. 화면 결과·비교 기록은 새로고침하면 초기화됩니다. 새 TRAIN을 추가한 경우에도 적재·전처리 저장 후 전체 다시 학습을 사용합니다. 작업 버튼은 이름이 고정되어 있으며 상태는 옆에 표시합니다. 기본과제는 테이블 생성 → 프로시저 등록을 각각 실행하고 최초/교체 적재도 구분합니다. 다시 시작할 때는 데이터 비우기·모델 삭제·확정 해제·실습 오브젝트 삭제에서 필요한 범위만 선택하세요. 미션은 제공된 정리 SQL을 직접 실행하고 창의는 직접 작성합니다. 미션의 스키마 조회는 원본 DATA → 전처리 PREPARED → 예측 PREDICT → 실행 프로시저 RUN 탭 순서입니다. RUN 탭에서 선택 미션의 전체 프로시저 생성 SQL을 복사하고 같은 발급 계정에서 직접 F5 실행합니다. 적용 안내는 현재 작업의 핵심 3단계로 요약하며, 오류 해결·터미널 명령·DB 확인 SQL은 필요한 항목만 펼쳐 봅니다. SQL 단계는 별도 색상으로 강조하며 선언·실행 분기·조회문은 각각의 원문으로 읽습니다.

CSV 검사의 DB 미사용과 미션 SQL 가이드의 직접 실행을 구분하세요. 흐름도는 실행 전 소스 안내이며 실제 결과는 작업 화면에서 확인합니다. 로컬 원문과 DB 원문이 다르면 USER_SOURCE를 비교합니다. 생성된 선택값 SQL은 파일 원문과 별도로 표시합니다. 직접 호출 예제는 sql/examples/run.sql입니다.
