5. 파일 저장과 실제 DB 반영은 별개입니다.

먼저 scripts/backup.ps1으로 소스를 보관하고, VS Code Oracle 연결과 Python의 student.env가 같은 본인 STUDENT 계정인지 확인합니다. 웹 서버 재시작만으로 SQL 파일이 DB에 반영되지는 않습니다.

수정한 것반영 방법추가 작업
패키지 내부 처리02_package.sql을 자기 계정에서 스크립트 실행하거나 db-init을 실행해 컴파일.오류 확인. 학습 설정·계산 논리가 바뀌었다면 재학습.
프로시저 이름·인자·반환 형식명세와 본문을 함께 컴파일. Python 호출·결과 처리도 저장.Python 서버 재시작, 호출·예측·표시 검증.
뷰 정의해당 CREATE OR REPLACE VIEW를 실행하거나 db-init으로 기존 뷰를 갱신.뷰 조회 확인. 특성·라벨을 바꿨다면 DB 데이터 재생성 후 재학습.
이미 생성한 테이블자기 스키마에 맞는 ALTER TABLE 등의 변경문을 별도 SQL 파일에 작성하고 직접 실행.컬럼·제약조건 확인, 관련 뷰·프로시저·Python·CSV 수정.

db-init은 테이블 구조를 자동 변경하는 도구가 아닙니다.

기존 OML_ 테이블의 CREATE TABLE 중복 오류는 건너뛰고 뷰·패키지는 다시 만듭니다. 이미 있는 테이블을 바꾸려고 01_schema.sql의 CREATE TABLE만 수정해도 기존 컬럼은 바뀌지 않습니다. 예를 들어 본인이 deploy/sql/03_changes.sql을 작성했다면 해당 파일은 직접 실행해야 합니다. 현재 db-init이 자동으로 실행하는 파일은 01_schema.sql과 02_package.sql뿐입니다. 기존 테이블을 무조건 삭제하고 다시 만들지 마세요.

# 뷰·패키지 수정 후 현재 초기화 경로로 반영
powershell -ExecutionPolicy Bypass -File .\scripts\db-init.ps1

# Python·화면·계정 설정을 바꾼 뒤
powershell -ExecutionPolicy Bypass -File .\scripts\restart.ps1

Oracle SQL Developer 확장에서는 자신의 연결로 SQL 파일을 열고 스크립트 실행 기능을 사용합니다. 패키지의 명세와 본문 사이, 각 문장 끝의 단독 / 구분자를 유지하세요. 확장의 DB 객체 화면에서 직접 수정했다면 최종 정의를 로컬 SQL 파일에도 저장해야 제출 ZIP에서 재현할 수 있습니다.

‘샘플 다시 만들기’는 현재 DB의 원본 주문에서 OML_FEATURES를 교체합니다. 본인이 업로드한 CSV를 유지해야 한다면 실행하지 마세요. 데이터·특성·알고리즘을 바꾸어도 모델이 자동으로 다시 학습되지는 않으므로 변경 후 필요한 재학습을 직접 수행합니다.

6. 반영 여부를 확인하고 오류 위치 찾기

아래는 자기 계정의 객체를 확인하는 읽기 전용 진단 쿼리입니다. 새로운 과제 모델의 구현 예시는 아닙니다.

SELECT USER FROM DUAL;

SELECT OBJECT_NAME, OBJECT_TYPE, STATUS
FROM USER_OBJECTS
WHERE OBJECT_NAME = 'OML_LAB'
ORDER BY OBJECT_TYPE;

SELECT TYPE, LINE, POSITION, TEXT
FROM USER_ERRORS
WHERE NAME = 'OML_LAB'
ORDER BY TYPE, SEQUENCE;

SELECT COLUMN_ID, COLUMN_NAME, DATA_TYPE, NULLABLE
FROM USER_TAB_COLUMNS
WHERE TABLE_NAME = 'OML_FEATURES'
ORDER BY COLUMN_ID;

패키지와 패키지 본문이 VALID인지 확인합니다. USER_ERRORS 결과가 있으면 TYPE·LINE·POSITION으로 해당 명세/본문의 위치를 찾아 수정하세요. 오류의 LINE은 패키지 단위 위치이므로 01·02 파일 전체의 줄 번호와 같다고 가정하지 않습니다.

  • 호출 인자 오류: 패키지 명세·본문·Python 인자 개수와 순서 확인.
  • 컬럼 없음·SQL 오류: 실제 DB 컬럼과 뷰 정의, SELECT의 별칭 확인.
  • 웹 입력/CSV 거절: validation.py와 HTML, PL/SQL의 조건을 함께 확인.
  • 결과 표가 비어 있음: JSON 키와 app.js가 읽는 키, 학습 상태 확인.
  • 원래 결과가 계속 나옴: 접속 계정·SQL 반영·재학습·서버 재시작·브라우저 캐시 순서로 확인.

변경 전후의 목적·파일·실행 결과를 보고서의 수행 기록에 남기고, 본인 수행 확인 질문에 설명할 수 있는지 점검하세요.
