03. 프로젝트 전용 가상환경 만들기

powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1

setup은 Python 3.12를 찾아 .venv를 만들고 reference/requirements.lock의 버전을 설치합니다. 동봉된 wheel이 있으면 오프라인 설치가 가능합니다. Oracle Instant Client도 runtime/instantclient에 준비합니다. 기존 Anaconda나 전역 PATH는 바꾸지 않습니다. Bypass는 이 명령의 PowerShell 프로세스에만 적용됩니다.

3.12를 다른 폴더에 설치했다면

아래를 실제 설치 경로로 바꾸세요.

powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -PythonExe "C:\Python312\python.exe"

Ctrl+Shift+P → Python: Select Interpreter → Enter interpreter path에서 .venv\Scripts\python.exe를 선택합니다. 편집기에서 선택한 인터프리터와 이미 열린 터미널의 Python은 다를 수 있으므로 다음 단계까지 확인하세요.

.venv와 .env는 다릅니다.

.venv/는 Python과 패키지를 분리하는 폴더입니다. security/student.env는 DB 접속 설정 파일입니다. 가상환경을 활성화했다고 DB 계정이 설정되는 것은 아닙니다.

05. 내 Oracle 계정 설정하기

setup이 생성한 security/student.env에서 계정 번호와 비밀번호를 본인 것으로 바꿉니다. 이 파일은 소스 백업·학생 ZIP에서 제외됩니다.

DB_USER=STUDENT01
DB_PASSWORD='강사가 알려준 내 DB 비밀번호'
DB_DSN=pcuora_low
WALLET_PASSWORD=
WALLET_ZIP=security/Wallet_PCUORA.zip
ORACLE_CLIENT_LIB=runtime/instantclient/instantclient_23_26

비밀번호는 작은따옴표로 감싸 공백과 #을 보존합니다. 작은따옴표는 \', 역슬래시는 \\로 이스케이프합니다. 설정 변경 뒤 웹을 재시작하세요. Wallet ZIP은 수정하지 않습니다. Thin 모드를 선택할 때만 ORACLE_CLIENT_LIB를 비우고 Wallet 다운로드 당시 암호를 WALLET_PASSWORD에 입력합니다.

VS Code Oracle 연결도 설정하기
  1. Oracle SQL Developer에서 새 연결의 표시 이름을 PCUORA_STUDENT01처럼 정합니다.
  2. DB 사용자명은 STUDENT01, 비밀번호는 본인 값입니다.
  3. Cloud Wallet → security/Wallet_PCUORA.zip → pcuora_low를 선택합니다.
  4. 연결 테스트 후 저장합니다. Python의 .env는 별도로 설정해야 합니다.

06. 테이블 생성 → 실행 → 중지·재시작

powershell -ExecutionPolicy Bypass -File .\scripts\db-init.ps1

db-init은 OML_ 테이블·뷰·OML_LAB 패키지와 작은 샘플을 준비합니다. 재실행 시 기존 데이터를 보존하며, 기존 BOOK/CUSTOMER/ORDERS는 수정하지 않습니다. http://127.0.0.1:22417에서 실습실을 열고 DB 확인 → 데이터 확인 → 학습 → 예측 순서로 진행합니다.

07. 소스 백업·압축과 과제 제출

스크립트결과포함 범위
backup.ps1backups/ 시간별 폴더공개 가능한 소스·SQL·샘플 CSV·참조 문서·잠금 목록

개인 과제 제출은 과제 제출 안내의 submit.ps1을 사용합니다. 백업은 매번 새 시간 이름을 사용하며 DB 테이블·모델이 아닌 소스를 백업합니다. 개인 .env·Wallet·설치파일·wheel·.venv·로그는 소스 백업에 포함하지 않습니다. 복원은 새 폴더에 소스를 풀고 수업용 설치자료와 Wallet을 별도로 준비한 뒤 setup → 계정 설정 → db-init 순서입니다.

백업은 허용된 경로와 파일 형식만 포함합니다. 새 폴더나 형식을 추가했다면 scripts/source_files.py의 목록도 검토하세요. 소스에 비밀번호를 직접 적으면 공개되므로 인증정보는 security의 개인 .env에만 둡니다.

VC++ x64 Runtime은 언제 설치하나요?

현재 기본 Windows Thick 연결은 Oracle Instant Client를 사용하므로 호환되는 VC++ v14 x64 Runtime이 필요합니다. 이미 설치되어 db-init이 정상 연결되면 추가 설치하지 않습니다. Windows 설정 → 앱 → 설치된 앱에서 Microsoft Visual C++ v14 계열 Redistributable (x64)을 확인하세요. 미설치 또는 버전 부족이 원인일 때만 Microsoft 공식 설치파일로 설치·업데이트합니다. Visual Studio 전체 설치는 필요하지 않습니다.
