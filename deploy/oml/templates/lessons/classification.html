“어느 범주에 속할까?”를 학습합니다.

분류는 입력 X에 대해 정해진 범주 y를 예측하는 지도학습입니다. 이 수업은 재구매/미구매 두 가지를 구분하는 이진 분류입니다. 도서 문의를 주문·배송·환불로 구분하면 다중 분류가 됩니다. 판매 금액처럼 연속적인 숫자를 예측하는 회귀와 구별하세요.

서점에서는 재구매 고객 안내, 장기 미방문 고객의 복귀 지원, 문의 유형 분류 같은 문제를 생각할 수 있습니다. 하지만 고객의 관심·환경·정책이 바뀌면 과거 패턴도 달라집니다. 예측은 사람을 확정적으로 규정하는 판정이 아닙니다.

OML_REBUY_DT: 7~9월 구매 특성 네 가지 → 10월 REBUY/NO_REBUY. 알고리즘은 해석하기 쉬운 Decision Tree입니다. 나머지 활용 사례는 아이디어 설명이며 완성된 별도 소스는 제공하지 않습니다.

의사결정나무는 어떤 질문을 고를까요?

의사결정나무는 데이터를 조건으로 나누면서 각 그룹의 정답이 더 비슷해지도록 학습합니다. 예를 들어 “마지막 구매가 얼마나 최근인가?”라는 조건으로 나눈 두 그룹의 재구매 비율이 뚜렷하게 다르면 유용한 분할 후보입니다. 조건과 경계값은 코드에 정답으로 고정하지 않고 TRAIN 데이터에서 선택합니다.

불순도: 정답이 얼마나 섞여 있을까?

이번 설정은 Gini 불순도를 사용합니다. 클래스 비율을 pk라 하면 Gini = 1 − Σ pₖ²입니다. 이진 분류에서 두 클래스가 반반이면 0.5이고 한 클래스만 있으면 0입니다. 분할 후 각 자식 노드의 Gini를 표본 수로 가중 평균하고, 분할 전보다 얼마나 줄었는지 비교합니다.

직접 움직여 보기 · 원리 모형

10명 중 재구매 고객이 5명이라면

Gini = 1 − p² − (1−p)² = 0.50

이 슬라이더는 공식 이해를 위한 계산입니다. Oracle 모델을 학습하거나 변경하지 않습니다.

부모 10명(재구매 5명)의 Gini는 0.5입니다. 5명씩 나눈 두 그룹이 각각 재구매 4명·1명이면, 두 그룹의 Gini는 각각 0.32입니다. 가중 평균은 0.32, 감소량은 0.18입니다. 더 큰 감소가 좋은 분할 후보가 되지만 지나치게 깊은 나무는 우연한 잡음까지 학습합니다.

깊이와 최소 표본 수

최대 깊이 4, 말단 노드 최소 5행, 분할 후보 노드 최소 10행으로 복잡도를 제한합니다. 이는 작은 실습을 위한 설정이며 항상 최적인 값은 아닙니다. 실제 모델 조회에서 분기 조건·노드 표본 수·예측 클래스를 함께 읽으세요.

새 입력은 학습된 조건을 따라 말단 노드로 이동하고 클래스별 추정 확률을 받습니다. Oracle의 반환 확률은 모델의 추정치입니다. “58%”가 그 고객 개인에게 객관적으로 보장된 확률이라는 뜻은 아니며, 확률의 신뢰성은 별도의 보정·평가가 필요합니다.

Oracle 문법을 역할별로 읽기

이 코드는 OML_LAB.TRAIN_CLASSIFIER에 들어 있는 동일한 모델 생성 호출입니다. 전체 소스에는 데이터 검사, 기존 실습 모델 교체, 버전 기록이 함께 있습니다.

DBMS_DATA_MINING.CREATE_MODEL2(

  mining_function     => DBMS_DATA_MINING.CLASSIFICATION,
  data_query          => 'SELECT * FROM OML_TRAIN_V',
  set_list            => cfg,
  case_id_column_name => 'CUSTOMER_ID',
  target_column_name  => 'LABEL');

CREATE_MODEL은 입력 테이블/뷰 이름과 설정 테이블을 받습니다. 이 프로젝트는 별도의 설정 테이블 없이 SQL 쿼리와 SETTING_LIST를 받는 CREATE_MODEL2를 사용합니다. 둘 다 DBMS_DATA_MINING 패키지의 모델 생성 방법입니다.

Python은 저장 프로시저를 호출합니다.

with conn.cursor() as cur:
    cur.callproc('OML_LAB.TRAIN_CLASSIFIER')

실제 코드의 학습 API가 이 호출을 수행합니다. 예측은 OML_LAB.PREDICT_RANK를 호출하고 OUT SYS_REFCURSOR로 두 클래스의 순위를 받습니다. 입력값은 바인드 변수로 전달합니다. 사용자의 문자열로 SQL이나 모델 이름을 조립하지 않습니다.

PREDICTION은 대표 예측 클래스 하나를, PREDICTION_SET은 클래스별 추정 확률 집합을 제공합니다. 실제 이 DB에서 집합 원소의 열 이름은 PREDICTION, PROBABILITY로 확인했습니다. 전체 소스는 확률 내림차순, 동률이면 라벨 순으로 순위를 정합니다.

실습: 내 입력으로 예측해 보기

  1. 데이터를 확인합니다. 실습실 데이터 탭에서 행 수·라벨·TRAIN/TEST 분포를 봅니다. 필요하면 제공된 CSV를 검증 후 적용합니다.
  2. Oracle에서 학습합니다. 모델 탭의 학습 버튼을 누릅니다. 새 모델이 현재 학생 스키마에 만들어집니다.
  3. 모델을 읽습니다. 노드별 표본 수, 분기 특성, 경계값과 설정을 확인합니다. “모델 파일” 대신 Oracle의 모델 상세 뷰를 조회합니다.
  4. 새 입력을 넣습니다. 관측기간 구매 횟수·총액·최근성·분야 수를 입력합니다. 정답 라벨은 넣지 않습니다.
  5. 순위를 해석합니다. 1위 클래스와 확률, 2위와의 차이를 기록합니다. 높은 순위는 높은 정확도와 같지 않습니다.
  6. 한 특성만 바꿉니다. 최근성만 바꿨을 때 결과가 변하는지 관찰하고 실제 분기 조건과 비교합니다. 이는 모형의 민감도 관찰이며 인과 실험은 아닙니다.

“얼마나 맞았나?”보다 자세히 보기

여기서 양성(positive)은 REBUY입니다. 혼동행렬의 행은 실제 정답, 열은 예측값입니다.

예측 REBUY예측 NO_REBUY
실제 REBUYTP: 재구매를 맞힘FN: 재구매를 놓침
실제 NO_REBUYFP: 재구매로 잘못 예측TN: 미구매를 맞힘
  • 정확도 = (TP + TN) / 전체. 불균형 라벨에서는 이 값만 보지 않습니다.
  • 정밀도 = TP / (TP + FP). 재구매라고 예측한 사람 중 실제 재구매 비율입니다.
  • 재현율 = TP / (TP + FN). 실제 재구매한 사람 중 찾아낸 비율입니다.
  • F1 = 2TP / (2TP + FP + FN). 정밀도와 재현율의 조화평균입니다.

분모가 0이면 해당 지표는 정의할 수 없어 “—”로 표시합니다. TRAIN의 다수 클래스를 항상 예측하는 기준과 비교하세요. 실습의 작은 TEST에서는 고객 한 명만 바뀌어도 점수가 크게 달라집니다. 평가 결과에는 표본 수를 반드시 함께 적습니다.

재구매 안내 비용을 줄이려면 높은 정밀도가, 잠재 재구매 고객을 놓치지 않으려면 높은 재현율이 중요할 수 있습니다. 목적 없이 정확도만 높이는 것이 목표는 아닙니다. 비용·임계값·검증 방식의 선택 근거를 과제에 적으세요.
