기본·미션·창의과제 실습 가이드

기본은 실행하며 이해하고, 미션은 선택 데이터의 SQL 가이드를 고치며 익히고, 창의는 직접 설계합니다.

세 과제는 현황 → 학습데이터 → 모델 생성·비교 → 예측 실행의 같은 화면 구성을 사용합니다. 기본은 버튼으로 실행하고, 미션·창의는 직접 SQL로 객체·모델을 만들고 CSV는 화면에서 적재한 뒤 웹에 연계합니다.

1. 과제별로 시작 방법이 다릅니다

로그인 버튼은 메인 본문에 입력 폼을 표시합니다. 로그인 후 메인의 접속 카드에서 학번·이름·발급 DB 계정·실제 접속 위치·연결 테스트 결과를 확인하고 함께 캡처해 PPT에 넣으세요. 기본·미션·창의과제는 그다음 메뉴에서 선택합니다.

기본과제 · 환경을 준비하고 실행

  1. 현황의 고정 기본 미션에서 데이터 조회·스키마 조회·CSV 다운로드로 주식 데이터를 확인합니다. 기본 미션은 다른 주제로 선택할 수 없습니다.
  2. 테이블 생성 → 프로시저 최초 등록 → 기본 CSV 적재 → RAW/CLEAN 전처리 저장 → 최초 학습 → 같은 TEST 비교 → 3단계 기본 모델 지정 또는 4단계 모델 선택 → 예측을 화면 버튼으로 실행합니다.
  3. SQL을 직접 바꾸지 않아도 실습할 수 있습니다. 코딩도움말의 화면 버튼 → 이벤트 → API → 서비스 → DB 연결 → SQL 상자를 눌러 실제 호출 파일과 코드를 확인하고 결과를 설명하세요.

미션과제 · 선택 데이터의 SQL 가이드를 적용하고 수정

  1. 예시 12종에서 미션 하나를 선택하고 CSV의 식별키·설명변수·타깃과 값을 확인합니다. 선택은 계정별로 저장되지만 DB 객체 생성·CSV 적재는 수행하지 않습니다.
  2. 스키마 조회의 ① 원본 DATA → ② 전처리 PREPARED → ③ 예측 PREDICT → ④ 실행 프로시저 RUN 순서로 테이블 SQL을 확인합니다. SQL은 선택 미션의 컬럼·타입·분류 이름을 반영합니다.
  3. 선택 미션 SQL 가이드의 테이블·프로시저 SQL을 복사해 실행하거나 내려받아 sql/custom/mission/01_tables.sql과 02_procedure.sql에 직접 저장·수정합니다. 다운로드·미션 선택은 로컬 파일을 자동으로 덮어쓰지 않습니다.
  4. 본인 발급 DB 계정으로 접속한 SQL Developer에서 계정 확인 → 테이블 SQL → RUN 프로시저 SQL 순서로 전체 F5 실행합니다. 화면에서 CSV를 적재한 뒤 가이드의 전처리·모델 생성 SQL을 실행합니다.
  5. 학습데이터·모델 생성·비교·예측 실행의 ? 코딩도움말에도 선택 미션에 맞는 SQL이 나옵니다. 가이드를 직접 실행하거나 SQL 파일을 수정·DB에 적용한 후 SQL 실행 결과 연계으로 연계합니다. 웹에서는 원본·준비값·모델 조회, TEST 평가·예측을 실행합니다. 테이블 생성·전처리·학습·삭제는 직접 SQL로 수행하고 CSV 적재는 화면에서 실행합니다.

테이블 생성 SQL은 각 CREATE TABLE 바로 위에서 해당 테이블의 존재를 확인하고 있으면 삭제합니다. 재실행하면 그 테이블의 기존 행이 삭제되며 DDL은 ROLLBACK할 수 없습니다. 일부 테이블만 필요하면 해당 탭의 SQL만 실행하세요. 미션을 바꾼 뒤에는 RUN 적용·CSV 적재·전처리 저장·재학습도 진행합니다.

창의과제 · SQL을 직접 작성

  1. 문제·데이터·특성·타깃·전처리·검증 방법을 직접 설계합니다.
  2. sql/custom/creative/01_tables.sql과 02_procedure.sql에 테이블과 프로시저를 직접 작성하고 같은 DB 계정에 적용합니다. 이 파일에는 시작할 때 지킬 이름·입출력 규칙만 있으며 실행 답안 SQL은 없습니다.
  3. 테이블·프로시저 생성과 전처리·모델 생성은 직접 SQL로 수행하고 CSV는 화면에서 적재합니다. 웹에서 연결·컬럼·프로시저 인자·실행 가능 여부를 확인한 뒤 조회·TEST 평가·예측으로 연계합니다. 생성·조회·전처리·모델·예측의 안내 쿼리는 제공하지 않습니다.

객체 없음·컴파일 오류·인자 불일치와 실제 DB 접속 실패는 다른 상태입니다. 창의는 진단을 보고 본인이 작성한 SQL을 고쳐 다시 확인하세요. 파일 저장만으로 DB는 바뀌지 않으며 SQL만 적용하면 서버 재시작은 필요 없습니다.

직접 SQL 수행 뒤에는 각 탭의 SQL 실행 결과 연계를 누르세요. 데이터 조회만으로 성공 기록이 생성되지 않습니다. 최종 현황의 N/M 완료를 클릭해 남은 작업을 확인하고, 과제별 성공 도장과 본인 정보를 PPT에 캡처하세요.

2. 고정 이름과 역할을 유지하세요

학번과 DB 계정을 구분하세요. 객체 소유자는 학생에게 발급된 DB 계정입니다. 아래 STUDENT00은 예시이며 본인 발급 계정으로 바꿉니다. 화면과 제공 SQL에는 로그인한 실제 계정을 붙여 테이블·프로시저·모델을 표시합니다. 다른 계정으로 접속한 경우 제공 SQL은 생성·삭제 전에 계정 검사에서 중단됩니다. 직접 작성할 때도 소유자와 접속 계정을 확인하세요.

역할·준비 순서기본미션창의
① DATA · 학습·TEST 원본STUDENT00.OML_BASIC_DATASTUDENT00.OML_MISSION_DATASTUDENT00.OML_CREATIVE_DATA
② PREPARED · 전처리 저장값STUDENT00.OML_BASIC_PREPAREDSTUDENT00.OML_MISSION_PREPAREDSTUDENT00.OML_CREATIVE_PREPARED
③ PREDICT · 예측 원본STUDENT00.OML_BASIC_PREDICTSTUDENT00.OML_MISSION_PREDICTSTUDENT00.OML_CREATIVE_PREDICT
④ RUN · 실행 프로시저STUDENT00.OML_BASIC_RUNSTUDENT00.OML_MISSION_RUNSTUDENT00.OML_CREATIVE_RUN

모델 이름도 STUDENT00.OML_BASIC_RAW_MODEL처럼 소유자를 붙입니다. 프로시저 선언·호출·내부 조회·적재에서도 같은 소유자를 사용합니다.

원본은 보존하고 전처리 값은 PREPARED에 저장합니다. 모델은 그중 선택 방식 + TRAIN + FIT_YN=Y인 행만 학습합니다. CASE_ID는 사례 식별키이며 설명변수가 아닙니다.

미션 가이드는 선택한 CSV에 맞습니다. 창의는 입력 특성·정답·분류 이름과 처리 방법을 직접 정하고 CSV·테이블·프로시저를 일치시킵니다.

3. 한 가지씩 바꾸고 결과를 비교하세요

실습실행 순서
정제 효과RAW 전처리 저장 → 최초 학습 → 평가·예측을 기록합니다. CLEAN도 따로 만들어 같은 TEST·예측 입력으로 비교합니다.
데이터 증가본인 계정의 DB에서 새 CASE_ID로 TRAIN 원본 추가 → VALIDATE → COMMIT → PREPARE → ADD_TRAIN → 비교합니다. 기본은 준비·학습을 화면에서, 미션·창의는 직접 SQL로 실행합니다.
학습할 행 변경DB에서 PREPARED 값·FIT_YN 수정 → COMMIT → 전체 다시 학습 → 비교합니다. 이때 PREPARE를 다시 실행하지 않습니다.

기본은 아래 작업을 화면에서 실행하고, 미션·창의는 SQL로 실행한 뒤 웹에서 상태와 결과를 확인합니다.

CLEAN은 RAW와 별도 모델입니다. ‘전체 다시 학습’은 선택 모델을 지우고 현재 학습 행 전체로 다시 만듭니다. 새 TRAIN도 적재·전처리 후 같은 버튼을 사용합니다.

전처리 저장을 다시 실행하면 선택 방식의 TRAIN/TEST 준비값과 수동 수정값을 교체합니다.
원본·프로시저 변경: 전처리 저장부터 실행.
준비값만 변경: COMMIT 후 재학습부터 실행.

TEST와 정답은 그대로 둡니다. 정제·데이터 증가가 점수 향상을 보장하지 않습니다. 웹의 일시적인 실습 결과는 새로고침·로그아웃 때 지워지므로 필요한 결과를 캡처하세요. 계정별 미션 선택 기록은 유지됩니다.

4. 직접 작성할 때 지킬 입출력 규칙

  • 미션: 가이드를 출발점으로 전처리·TRAIN 오류행의 학습 제외 기준과 사유(FIT_YN·EXCLUDE_REASON)를 점검·보완하고 바꾼 이유를 설명합니다. 고정 TEST 전체와 정답은 보존합니다.
  • 창의: TRAIN·TEST·별도 예측 원본의 합계는 10,000건 이하입니다. SQL로 만든 행과 누적 적재도 포함합니다. RAW/CLEAN 준비행은 원본 사례로 다시 세지 않습니다.
  • CSV: 기본의 웹 적재는 파일당 5,000행 / 2 MiB. 미션·창의도 직접 만든 대상 테이블에 CSV를 업로드합니다. 창의 원본 전체 10,000건 제한은 직접 SQL 생성·누적 적재에도 적용합니다.
고정 관리 컬럼과 학습 대상

CASE_ID는 사례 번호입니다. PREPARED에는 PREP_MODE·SOURCE_KIND·USE_YN·FIT_YN·EXCLUDE_REASON·PREPARED_AT도 유지합니다. 키는 PREP_MODE + SOURCE_KIND + CASE_ID입니다.

USE_YN은 원본 사용 여부, FIT_YN은 실제 학습 여부입니다. TRAIN 중 사용 가능하고 정답이 유효한 행만 FIT_YN=Y로 만듭니다. TEST·예측·원본 N 행은 학습에서 제외합니다. 전처리 저장과 모델 학습은 분리합니다.

프로시저 인자 · 실행 명령 · 결과 컬럼

RUN의 입력 인자는 p_action IN VARCHAR2·p_mode IN VARCHAR2, 출력은 p_result OUT SYS_REFCURSOR·p_sql OUT CLOB입니다. p_mode는 RAW/CLEAN이며 한 번에 한 방식만 처리합니다.

p_action처리·출력 규칙
PREPARE선택 방식의 TRAIN/TEST 준비값 저장. 실패하면 이전 준비값으로 롤백.
INIT모델이 없을 때 선택 방식의 학습 제공 행으로 최초 생성.
RETRAIN / ADD_TRAIN선택 모델을 현재 FIT_YN=Y 전체로 재생성. 전처리는 다시 실행하지 않음.
VALIDATE원본 검사. 모델 없이 가능하며 DDL·COMMIT 없음.
EVALUATE같은 Y/TEST 전체 평가. 출력: VARIANT·ACTUAL·PREDICTED·N.
PREDICT예측 원본을 같은 규칙으로 전처리 저장 후 예측. 출력: CASE_ID·PREDICTED·PROBABILITY.
DELETE선택 모델만 삭제. 테이블·다른 모델 유지.

p_result는 결과 표, p_sql은 실제 결과·학습 SQL 또는 삭제 PL/SQL 원문입니다. TRAIN은 이전 호출 호환용입니다. PROBABILITY는 예측한 분류의 0~1 확률이며 추가 결과 컬럼도 웹에 표시됩니다.

생성·컴파일·실행 오류가 있을 때
  • 객체 없음: 미션은 선택 미션 SQL 가이드를, 창의는 직접 작성한 SQL을 같은 계정에 적용한 뒤 연결을 다시 확인합니다.
  • 컴파일 오류: 진단에 표시된 오류 줄·메시지를 보고 수정 후 프로시저 전체 F5. DB 저장 프로시저의 VALID 여부와 수정 내용을 확인합니다.
  • 인자·컬럼 불일치: 위 고정 이름과 입출력 규칙에 맞춰 SQL을 수정·적용합니다.
  • 기존 컬럼 변경: 데이터를 보존하려면 필요한 ALTER를 직접 적용합니다. 미션의 DROP 포함 생성 SQL을 다시 실행하면 해당 테이블 행이 삭제됩니다.
  • 모델 생성 실패: 모델 생성·삭제는 자동 커밋됩니다. 원본을 중복 추가하지 말고 오류를 고쳐 다시 학습하세요. Oracle의 DM$ 내부 객체는 직접 삭제하지 않습니다.

코딩도움말은 여섯 단계의 흐름에서 그룹과 세부 항목을 누르면 파일·줄 번호·원문을 보여 줍니다. SQL 단계는 별도 색상으로 표시하며 DB 미사용·웹 실행·SQL Developer 직접 실행을 구분합니다. 기본은 이 흐름으로 동작을 확인하고, 미션은 선택 데이터의 실행 SQL·수정 위치를 활용합니다. 창의에는 안내 쿼리가 없으므로 오류 진단과 입출력 규칙에 따라 직접 구현합니다.
