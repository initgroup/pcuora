# 평가 기준: 기본 50 · 미션 30 · 창의 20

최신 사용자 요청에 따라 평가 영역을 기본과제·미션과제·창의과제로 구분한다.
최신 배점은 기본과제 50점, 미션과제 30점, 창의과제 20점이며 총 100점이다.
본인 수행·이해도 40점은 유지하고 나머지 세부 항목을 새 영역 합계에 맞춘다.

| 영역 | 세부 항목 | 배점 |
|---|---|---:|
| 기본과제 | 본인 수행·수업 이해도 | 40 |
| 기본과제 | 제공 데이터·전처리 이해 | 5 |
| 기본과제 | 검증·결과 해석 | 3 |
| 기본과제 | 재현성·제출 완성도 | 2 |
| 미션과제 | 문제·활용 목적 | 5 |
| 미션과제 | 준비·학습·조회·예측 실제 동작 | 20 |
| 미션과제 | 자기 계정·데이터·프로시저 제약 준수 | 5 |
| 창의과제 | 샘플과 구별되는 설계 | 10 |
| 창의과제 | 변경 이유·실제 사용 상황 | 10 |
| 합계 | 기본 50 + 미션 30 + 창의 20 | 100 |

본인 수행·이해도 40점은 전체 과제의 직접 실행·설명을 확인하는 공통 평가다.
점수는 기본과제 영역에 한 번만 합산한다. 공통 샘플 실행만으로 50점을 자동 부여하지 않는다.
데이터·평가·재현성과 본인 수행의 근거를 함께 확인한다.

## 세부 평가 근거

- 본인 수행·이해도 40: 직접 실행 10, 라벨·분할·누수 설명 10, Python→PL/SQL→Oracle 흐름 10, 현장 입력 변경·오류 진단·결과 해석 10.
- 미션 해결 30: 문제·활용 목적 5, 준비→학습→조회→새 입력 예측의 실제 동작 20, 자기 계정·작은 데이터·프로시저 호출 등 제약 준수 5.
- 제공 데이터·전처리 이해 5: 제공 데이터의 행 단위·출처·정답 근거 설명 2, 결측·오류·이상치와 공통 전처리 설명 2, 분리·누수 방지 설명 1.
- 검증·해석 3: 보지 않은 데이터·다수 클래스 기준 비교 1, 혼동행렬·정밀도·재현율·오분류 설명 1, 한계·개선 방향 1.
- 창의성 20: 구별되는 질문·라벨·특성·활용 설계 10, 변경 이유와 사용 상황 연결 10.
- 재현성·제출 2: Python·프로시저·DDL 소스·설치/실행 안내·잠금 목록·PPT 원본·보고서·작업 기록·금지 파일 제외.

기본과제는 제공된 공통 사이트를 오류 없이 실행하고 결과를 캡처해 PPT로 설명하는 것이다.
미션과제는 번호가 붙은 12종 중 하나를 선택한다. 선택 미션의 가이드 SQL로 DATA·PREPARED·PREDICT 테이블과 RUN 프로시저를 생성·수정하고, CSV는 화면에서 적재한다. RAW/CLEAN 전처리·학습은 직접 SQL로 수행한 뒤 SQL 실행 결과 연계 버튼으로 확인하고 웹에서 TEST 평가·예측을 실행한다.
설명변수 NULL 행과 범위 밖 행은 TRAIN에서 USE_YN=N으로 제외하고 오류를 ERROR_LOG에 기록한다. 정답 수정 SQL은 제공하지 않는다. TEST는 고정 전체로 평가하며 제외하지 않는다.
창의과제는 직접 만든 데이터로 같은 두 테이블·단일 프로시저 구조의 적재·정제·모델·평가·예측을 완성한다. 원본 사례는 TRAIN·TEST·예측 합계 10,000건 이하이고, 본인 생성·적재 프로시저에서 확인한다. UI 디자인 수정은 요구하지 않는다.
창의과제는 100점 안의 20점이며 별도 가산점으로 표현하지 않는다.

학생 직접 코딩과 AI 보조 활용을 권장하되 본인 실행·설명·검증으로 이해도를 확인한다.
공통 샘플 재사용·정상 개념 토론과 과제 복제를 구분하며, 복제 제공자와 이용자는 모두 감점한다.
정제 성능 향상 자체를 보장하거나 TEST·라벨·결과 조작을 점수 근거로 삼지 않는다.

학생 안내는 downloads/COM22417_과제설명및평가.html에 단일 HTML로 제공한다.
미션·창의과제의 웹 연결은 backend/assignment_templates.py와 공통 HTML·JS로 제공한다. 학생은 DB 테이블·단일 프로시저와 실제 모델·평가·예측을 구현한다. 사용자 패키지·뷰·함수는 만들지 않는다. 고정 객체 이름·입출력 규약 안내는 reference/student/assignment-template-guide.html로 학생 ZIP에 포함한다. 웹 템플릿 제공 자체를 학생의 DB 구현 완료로 평가하지 않는다.
이 Markdown과 과거 평가 소스는 학생 ZIP에 포함하지 않는다.

최종 현황의 과제별 성공 도장은 기능 수행 증적이며 점수를 자동 판정하지 않는다. 네 단계의 성공표·세부 작업 및 본인 정보를 PPT에 담고 배점은 위 기준으로 평가한다. 통합 안내는 개발환경 설정·과제 수행방법·과제 평가 기준 3개 메뉴로 제공하고 ZIP에 같은 원본을 포함한다.
